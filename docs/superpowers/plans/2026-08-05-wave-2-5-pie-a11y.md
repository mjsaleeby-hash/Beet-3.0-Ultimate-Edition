# Wave 2.5 — Pie Polish, Legend Accessibility, Percentage Contrast — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make the pie chart's legend a keyboard- and screen-reader-accessible surface with readable percentages in light mode, and collapse the chart's two disagreeing "too small to draw" thresholds into one.

**Architecture:** The legend is the accessible representation of the donut, not decoration beside it — the chart renders up to 11 slices distinguished by colour alone, and the legend is the required non-colour fallback table. So legend rows become chrome-free `Button`s (focusable, Space/Enter-activatable, exposing the Invoke automation pattern that matches "navigate into this folder"), the percentage text stops being painted in the slice colour, and a single `MinVisiblePercentage` constant on `PieSlice` feeds both the render decision and the legend's negligible styling.

**Tech Stack:** .NET 8 / WPF (SDK pinned 8.0.x by `global.json`), xUnit + FluentAssertions, `Themes/Light.xaml` + `Themes/Dark.xaml` resource dictionaries merged via `App.xaml`.

**Spec:** `docs/superpowers/specs/2026-08-05-wave-2-5-pie-a11y-design.md` (approved 2026-08-05)

```csharp
    /// <summary>
    /// The smallest share of the total that still earns a drawn wedge.
    /// ONE constant feeds both the render decision (<see cref="IsRenderable"/>) and the
    /// legend's dimmed styling (<see cref="IsNegligible"/>). They were previously two
    /// separate numbers — a 0.1-degree sweep guard (0.028%) in PieChartControl and 0.05%
    /// here — so slices between them got a legend row with no wedge behind it.
    /// </summary>
    public const double MinVisiblePercentage = 0.05;

    /// <summary>Whether this slice is too small to render visibly.</summary>
    public bool IsNegligible => Percentage < MinVisiblePercentage;

    /// <summary>
    /// Whether the chart should draw a wedge for this slice. Deliberately trivial: its
    /// value is that the render decision has exactly one home, so the control cannot
    /// invent its own threshold again.
    /// </summary>
    public bool IsRenderable => !IsNegligible;
```

```csharp
    /// <summary>
    /// A pie wedge that reports itself as neither content nor a control to assistive tech.
    /// The wedges are decorative: every value they encode is present as text in the legend,
    /// which is keyboard accessible. Measured with Accessibility Insights — without this,
    /// each wedge surfaces as an anonymous node, so a screen-reader user wades through
    /// eleven unlabelled shapes before reaching the data.
    /// Suppression lives on the Path rather than on the UserControl's peer deliberately:
    /// filtering the control's children by peer type would also catch the legend buttons,
    /// because ButtonAutomationPeer is itself a UIElementAutomationPeer.
    /// </summary>
    private sealed class SlicePath : Path
    {
        protected override System.Windows.Automation.Peers.AutomationPeer OnCreateAutomationPeer()
            => new SlicePathAutomationPeer(this);

        private sealed class SlicePathAutomationPeer(SlicePath owner)
            : System.Windows.Automation.Peers.FrameworkElementAutomationPeer(owner)
        {
            protected override bool IsContentElementCore() => false;
            protected override bool IsControlElementCore() => false;
        }
    }
```

Then in `CreateSlicePath`, change the object being constructed from `new Path` to `new SlicePath` — every other line of that method stays as it is, since `SlicePath` is a `Path`.
